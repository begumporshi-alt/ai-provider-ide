## Testing gotcha (router-core)

`ExecutionEngine.executeText` returns a **lazy async generator** — no attempt starts, and no
permit is acquired, until you begin iterating `chunks`. To hold a slot in a test you must start
iteration (`exec.chunks[Symbol.asyncIterator]().next()`) and `await` a tick; calling
`executeText` alone does nothing. Real `ManifestInterpreter`s over a gated `HttpPort` are the
cleanest way to fake adapters — no hand-written AdapterInstance needed. Also: usage is only
captured from `$.usage` on a **stream chunk** (SSE), so scripted chat responses must emit
`data: {"usage":{...}}` or token counts/cost stay 0.

## That assumption was then MEASURED — and it was FALSE (real bug, fixed)

Built a standalone AppKit/WKWebView harness in /tmp/wvprobe (`swiftc main.swift -o x`, works:
`swiftc` is present via full Xcode, GUI session available, `osascript` works). ~60 lines: a
webview with `setInterval` posting `webkit.messageHandlers.tick`, UI window hidden after a
warm-up phase. This is the way to test platform behaviour here — no repo changes needed.

**Result — a window that was never composited has its JS SUSPENDED, and it stays suspended
exactly when nothing else is on screen** (ticks / 24s, 2s timer):

| how the window is shown                 | ticks |        |
|-----------------------------------------|-------|--------|
| never ordered in (`visible(false)`)     | 0     | DEAD   |
| `orderFront` + `orderOut` immediately   | 0     | DEAD   |
| `orderFront` + `orderOut` after 16ms    | 0     | DEAD   |
| `orderFront` + `orderOut` after 300ms   | 8     | ALIVE  |
| `orderFront` + `orderOut` after 1000ms  | 8     | ALIVE  |
| shown once, then `orderOut` (UI window) | 10    | ALIVE  |

tao's `visible(false)` NEVER calls `makeKeyAndOrderFront` (tao platform_impl/macos/window.rs
line ~630: `if visible { if focused {...} else {...} }`). So `.visible(false)` = row 1 = the
worker ran while the UI was up and DIED the moment the app went to background. **The dedicated
worker window was a regression against background mode**, which had worked when the bridge ran
in the always-displayed UI window.

**Ruled out:** App Nap (suppressing via `ProcessInfo.beginActivity` changes nothing — it's
WebKit, not power management). Off-screen parking (macOS CLAMPS windows back into view:
requested x=-4000 → actual x=480 — so there is no invisible warm-up).

**Fix (committed 99576c2):** create the worker window `visible(true)` + `focused(false)` +
undecorated + small, then `hide()` after `WORKER_WARMUP_MS = 1000` (3x the proven 300ms min).
`focused(false)` → tao uses `orderFront` not `makeKeyAndOrderFront` (verified in tao source),
so no key-window steal — and `orderFront` is what the measurements were taken on.
Cost: a ~220x140 undecorated window is briefly visible when the gateway starts, once/session.

Measured hidden cadence ~0.33/s, worst gap 3.0s → `HEARTBEAT_STALE_HIDDEN_MS = 30_000` has 10x
headroom (throttling can't trip it; a truly dead renderer still is caught).

**Lessons:**
- "Hidden" is not one state. Never-shown vs shown-then-hidden behave completely differently.
  Any future Tauri window created hidden-from-birth needs the same warm-up.
- Measure platform assumptions with a tiny harness; don't leave them as documented caveats.
- Put the measurement table in a comment next to the constant so nobody sets it to 0.

## Competitive landscape checked: OmniRoute · FreeLLMAPI · 9Router

All three are **MIT, local-first, self-hosted** — none is a hosted SaaS for the request path.
All three run the router in a **Node process** (Express or Next.js) + SQLite + a web dashboard.
None runs the router inside a webview. Ports: OmniRoute & 9Router `20128`, FreeLLMAPI `3001`.

| | OmniRoute | FreeLLMAPI | 9Router |
|---|---|---|---|
| Stack | TS/Node, Next.js dashboard | TS/Node, Express + SQLite, React/Vite | TS/Node, Next.js 16, SQLite |
| Desktop | Electron + **OmniRouteTray (Tauri, 3rd-party `zoispag/omniroute-tray`)** | Electron (macOS .dmg / Win .exe) | none (web dashboard) |
| Routing | `auto` scored on 16 factors + **19 strategies**, 4-tier cascade | 6 strategies, fallback chain, `fusion` panel | 3-tier fallback combos (subscription→cheap→free) |
| Resilience | circuit breaker + key cooldown + model lockout (3 layers) | key cooldown + rotation | multi-account round-robin, fail-open |
| Keys | AES-256-GCM in SQLite, key pools | AES-256-GCM in SQLite | SQLite + OAuth refresh, HMAC-signed tokens |
| Cost | per-key **USD quotas**, cost telemetry headers | rate/quota only (free tiers) | per-provider limits; cost is **display-only "savings tracker"** |
| Headline feature | token compression 15–95%, MCP (110 tools) + A2A | free-tier aggregation ~7.4B tok/mo | RTK compression 20–40% input, Caveman −65% output |

**Gaps for us, ranked:** (1) **prompt/context compression** — headline feature of all three, we
have none (RTK is Rust, 40k★; Caveman/LLMLingua-2). (2) **circuit breaker** — they cool down a
failing provider/key/model; we only have a semaphore + per-provider limiter. (3) **subscription /
OAuth tier** (Claude Code, Cursor, Codex) above API keys. (4) **signed hosted model catalog feed**
— FreeLLMAPI charges $19/yr for live vs 30-day-lagged, Ed25519-pinned; a real business model.
(5) routing-decision response headers (`X-Routed-Via`, `X-OmniRoute-Decision`).

**Where we are ahead — defend these:** OS keychain + key-blind egress (Rust sentinel injection,
secret never in JS). All three decrypt keys inside the JS process; ours is strictly stronger.
Also: real per-app keys + enforced monthly cap (vs 9Router's display-only, FreeLLMAPI's rate-only),
and a genuinely native Tauri shell rather than Electron.

**Validates our plan:** the ecosystem pattern is *Tauri/Electron shell supervises a Node router*
(OmniRouteTray is literally that). So R1-v2 "Node sidecar" is the right target, and the
webview-hosted bridge is the outlier — consistent with what we just measured.

## FIXED: gateway tool loop — two modes, owned by whoever declares the tools (commit 31edd6f)

**Pass-through** (client sent its own `tools`): emit calls on the wire, end the request, never
execute them. **Gateway** (client sent no tools + toggle on): supply `AGENT_TOOLS`, execute in
the Rust host, feed results back, keep going until the model stops. Mercury-2.5 inline markers
are neither → always executed locally, filtered from the client stream.

Rust changes worth remembering:
- `GatewayCore::reply()` now returns **bool** (was `()`), and `gateway_chunk` returns `Err` when
  nobody is listening. That is the bridge's only backpressure signal — this is what stops the
  runaway loop. Pattern: any fire-and-forget invoke from a long-running JS loop needs a way to
  learn the consumer is gone.
- Bridge loop capped at **8** iterations (matches `agentLoop.ts`); was `while (true)`.
- Assistant `tool_calls` turn MUST be pushed before `role:"tool"` results — providers 400 on a
  tool message that answers nothing.
- Tool calls are emitted **awaited** before `gateway_done`: same channel, and a Done that lands
  first looks like a finished request with no calls in it.
- Deleted rather than repaired: `BridgeMsg::FollowUp`, `BridgeMsg::ToolResult`,
  `gateway_re_dispatch`, `gateway_followup`, `re_dispatch_with_tool_results`. Removing a variant
  means editing every match arm — there were 6 across 4 dialect handlers.
- **Sandbox default root is now `~/AI-Provider-Router-Workspace`** (`default_workspace_root()`),
  NOT `std::env::current_dir()` (which is `/` for a Finder-launched app) and NOT `$HOME`.
- Result: `cargo check --lib` is **warning-free** for the first time (was 7).

Gate: 82 Rust + 261 TS green. 5 new gateway tests: pass-through stream terminates without
emitting a stop finish, pass-through non-stream returns `tool_calls`, `reply()` reports no

## ROOT CAUSE FOUND + FIXED: gateway ACL (commit 74e9c29)
- `gateway.log` gave it immediately: `worker error: Command plugin:event|listen not allowed by ACL`
- `capabilities/default.json` had `"windows": ["main"]`. The gateway worker is its own window
  (audit R1) and had **no capability at all** -> `listen('gateway-request')` denied ->
  `startGatewayBridge()` throws at that await -> bridge never registers -> no heartbeat ever ->
  ~30s later status flips to Stopped -> Start then no-ops (bound socket looked healthy).
- **App commands are NOT ACL-gated** (schema has no `allow-gateway-*`) — only *plugin* commands
  like `plugin:event|listen`. That's why `invoke` worked and the worker could report its own
  error while being unable to listen.
- Fix: `capabilities/gateway.json`, `windows: ["gateway"]`, permissions
  `core:event:allow-listen` + `core:event:allow-unlisten` only (no opener/window/dialog).
- **Lesson: any new Tauri window needs its own capability, or it silently gets NONE.**
  A window without one gets no permissions and fails on the first plugin command — inside an
  invisible window, so the failure is unobservable without a log.
- `gateway_heartbeat` logs "worker reported in after Nms quiet" when N > 5s (first boot +
  recovery), so the fix is verifiable from the log alone.
