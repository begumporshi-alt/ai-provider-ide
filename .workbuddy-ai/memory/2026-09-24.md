### Two structural decisions, both forced by Rust rather than chosen

- **The context is a `trait PlanContext`, not a struct of `&'a dyn Fn` fields.** A struct holding
  `&'a dyn Fn(..)` forces every test to keep its closures alive longer than the context built from them;
  `&|pid| ...` is a borrow of a temporary and does not compile. A trait lets the fixture *be* the context,
  which is also what the TypeScript is (an object literal with methods).
- **`Candidate` moved out of `core::engine` into `core::planner`.** Its increment-7 doc-comment parked it in
  the engine only "because the planner itself is not ported yet"; the planner now owns its output type. The
  engine imports it, so no call site changed. `ProviderRow`/`ApiKeyRow`/`ModelRow` gained `Clone`, because the
  TypeScript's `Candidate` holds *references* and the port clones. **After removing the struct, `ModelRow`
  became unused in non-test engine code** — it is imported inside `mod tests` so a plain `cargo build` warns
  about nothing.

### Three provably-equivalent divergences (each pinned by a test)

1. **`rem_euclid` replaces JavaScript's `%` *plus* its negative `slice` indices.** `-1 % 3` is `-1`, and
   `slice(-1)`/`slice(0, -1)` count from the end — so `start = -1` on three keys means "begin at index 2",
   which is exactly `rem_euclid(3)`. Total and panic-free where a literal `%` would produce a `usize` panic.
2. **The TypeScript's `if (!ctx.pricingFor)` guard is unobservable** once an absent price is `None`: every
   rank is `None`, every comparison is `Equal`, and a stable sort is the identity. So `pricing_for` is a
   **required** trait method with no default body — this crate's rule — and "no pricing" is one of its
   answers rather than a missing one. (Note the tension with the crate's "no default body" rule and why the
   rule still wins: the optionality *is* the value.)
3. **Dedup key is a `(provider_id, native_id)` tuple**, not `` `${providerId} ${nativeId}` `` — the string
   collapses `("a b","c")` with `("a","b c")`.

### Two source behaviours kept, both now pinned

- **`orderCarriers` decides by `wanted.some(...)`, so ONE carrier asking for `cost_spread` reorders every
  other carrier on the list**, including providers whose own strategy is something else.
- **A *disabled* provider still claims its own qualifier.** `stripClientNamespace` and the qualified-id lookup
  read `ctx.providers` regardless of status, while `buildPlan` requires `enabled`. So `a/m1` resolves as
  qualified against a disabled `a`, `qualified` suppresses the bare-id fallback, and the plan comes back
  **empty** even though another enabled provider carries a model literally named `a/m1`. That is the source's
  "never silently reroute" rule reaching further than its comment describes.

## Increment 12 — `core/ledger.rs`, the usage ledger (Phase 3 continues)

The blocker for the model router. `model-router.ts` calls `ledger.append()` in `generateText`,
`generateImage`, `complete`, and `recordNoRoute`; without a Rust ledger, every one of those methods
would be stubbed at its append. `usage-ledger.ts` is 115 lines: an in-memory ring buffer (`Vec` in
TypeScript, `VecDeque` in Rust — `O(1)` pop_front vs `O(n)` splice) plus an optional `LedgerSink` for
persistence.

`LedgerRow` already existed as `persist::LedgerRow`; it gained `Clone` and `Debug` so `query` can
return owned rows and the test spy can derive them. The port adds only the *buffer* and the *query*
surface.

`LedgerSink` is a trait (not `&dyn Fn` fields) — same lesson as `PlanContext`. The one method returns
`Result` so a full disk is observable rather than swallowed.

`is_none_or` replaces `map_or(true, ...)` — a clippy lint (`unnecessary_map_or`) that is also
clearer: "if None, true; if Some, apply the predicate" is exactly what the filter needs.

compile). Gate green: fmt, clippy -D warnings, 653/0 tests, `--no-default-features --all-targets`.

### 13a — `AttemptLabel`, and the parked decision closed in the *other* shape

`AttemptOutcome` gained `label: Option<AttemptLabel { provider_slug, key_label }>` — **two fields, not
the joined `slug/label` string increment 11b's note proposed.** The joined string is the cheap option
and it is wrong: `fallbackChainJson` is `{provider, key, cls}` as three *separate* JSON fields
(`Activity.tsx` / `Context.tsx` read them separately), so it would have to be split again, and a label
containing the separator splits in the wrong place.

The cost the note *did* predict was real and was paid: **`AttemptOutcome` is no longer `Copy`**, so two
call sites read `(outcome.cls, outcome.retry_after_ms)` *before* the push instead of after.
`AllAttemptsFailed::describe()` renders `slug/key:CLS` when labelled and `CLS:status` when not — the
unlabelled shape says it *cannot* name the attempt rather than forging one.

### 13b — `core/router.rs` (2,644 lines; 1,506 of them tests; 50 tests)

**Three findings came from failing tests, not from reading.** All three compile and look right:

1. **`complete`'s terminal error was `NoRoute`, and `NoRoute` is an HTTP status.** The source throws a
   plain `Error` whose text lacks the phrase `gatewayStatus` maps to `404`, so a Generator failure is a
   `500`. Reusing `NoRoute` silently changed the status a client sees. Fixed with a distinct
   `SystemAiUnavailable`, and the test now asserts `!matches!(.., NoRoute)` so it cannot be folded back.
2. **The first fall-through test asserted the wrong loop.** It assumed a per-*key* retry; the source's
   `modelOrder` falls through per *model*, so a provider whose first model returns nothing is left
   entirely. Rewritten to assert the call log `["text:key:k1|m1", "text:key:k3|m2"]` — `k2` is never
   reached.
3. **The image failure path writes no ledger row — the source, not a gap.** `generateText` ends in
   `wrapLedger`, which catches `AllAttemptsFailed` and appends; `generateImage` has no wrapper and
   throws before its `append`. Pinned with a comment, because it is what a later reader "fixes".

**`RouterError::Text` is boxed, and `execute_text`'s allowance was NOT inherited.** Clippy raised
`result_large_err` on five returns and `large_enum_variant` on the enum. Measured: `TextFailure` 616,
`NoRoute` 72, `AllAttemptsFailed` 48, versus `TextSuccess` 592, `ImageResult` 48, `String` 24, `()` 0.
The error outgrows the payload by **8× to 77× on four of five returns**, so the lint's premise holds
here — unlike `execute_text`, whose `Ok` arm carries the same 536-byte `Candidate` the failure does and
where a box buys 16 bytes. `RouterError` 616 → 80. The arithmetic is asserted by
`the_error_is_boxed_because_it_outgrows_every_payload_but_the_text_one`, which fails if a future `Ok`
type grows past the error and the decision needs re-arguing.

**Two source asymmetries kept and pinned:** `complete` does *not* call `syncConcurrency()` (so a stored
cap reaches the Generator only on the next UI/gateway request), and it writes no `fallbackChainJson`
(`NULL`, not `"[]"` — `"[]"` would mean "no attempts to record").

**`E0521` reappeared, exactly as the engine's note documents it.** Handing the seam
`on_usage.as_deref_mut()` off the request field does not compile — the borrow must outlive
`generate_text`. Two local forwarding closures fix it. But the binding *outside* each closure is a plain
move: `clippy::needless_option_as_deref` is right that `as_deref_mut()` on a local
`Option<&mut dyn FnMut>` is a no-op, and only the reborrow *inside* the closure is load-bearing. Dropping
it also made `mut` on the destructured fields unnecessary.

**Test fixtures leak two adapters on purpose.** `&Always(adapter.clone())` is a temporary that cannot
outlive the call (`E0716`, ~20 sites), so `factory()` `Box::leak`s one per test. Rejected the
alternative: an `Arc<dyn AdapterFactory>` field would make the router own a seam the source's
`AdapterRuntime` outlives.
