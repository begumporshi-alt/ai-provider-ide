## Increment 27b — aiproviderd subcommands: install / uninstall / status

**Context**: launching the headless agent required a manual plist + copy + `launchctl bootstrap`
dance from Terminal.app. The sandbox blocks `launchctl` because it needs the user's Aqua session.

**Changes**:
- Added `aiproviderd install`, `aiproviderd uninstall`, `aiproviderd status` subcommands in
  `src/bin/aiproviderd.rs`. Each calls `service::install`/`uninstall`/`status` internally.
- `install` copies the running binary to `~/Library/Application Support/dev.aiprovider.router/bin/aiproviderd`,
  writes the plist with `AIP_DATA_DIR` set, and runs `launchctl bootstrap gui/$(uid)`.
- No keychain prompt, no manual plist editing, no Terminal.app. Run `aiproviderd install` from
  any shell.

**Note**: the subcommand dispatch happens before `#[tokio::main]`'s store setup, so they work
with `--no-default-features` (no Tauri, no keyring, no store).

## Increment 27a — keychain removed; secrets moved to `.secrets.json`

**Context**: Tushu found the keychain prompt annoying on every rebuild. Decision: replace the OS
keychain with a file-backed store in the app data dir. No keyring dependency, no code-signing
dependency, no SecurityAgent prompt.

**Changes**:
- `vault.rs` rewritten: `keyring::Entry` → JSON file (`<data_dir>/.secrets.json`, mode 600).
  The file is written atomically (tmp + rename) to prevent partial writes.
- `set_data_dir(&Path)` exported; `aiproviderd` calls it before opening the store.
  `tauri/app.rs` calls it right after resolving `app_data_dir`, before `Store::open`.
- `keyring` removed from `Cargo.toml`.
- 503 message in `gateway.rs` updated: "the secrets file could not be read" instead of
  "the OS keychain did not respond; approve the keychain prompt".

**Migration**: existing keychain items are abandoned, not migrated. The master key is re-minted
on the next `ensure_master_key` call; provider keys need one re-entry in the UI. Acceptable for
a local-only tool in development.

## Increment 26z — launchd_live label collision found on third Aqua run

**Context**: the second Terminal.app run (after `ee435d3`) showed test 1 green
(`marker written = true`) but test 2 green via the `SKIP: no Aqua session`
early-return path — it never installed, never probed port 8800, never ran
`app_listener_action`. The exit code was 0 but the real assertions never fired.

**Root cause**: both tests called `launchctl bootstrap gui/501` under the same
label (`dev.aiprovider.router`) in the same gui domain. Whichever test registered
its plist second got I/O error 5 — the *identical* error code a genuine
no-Aqua-session failure produces. The `no_aqua_session` check matches on that
message, so test 2's `bootstrap` rejection (label already loaded) was
misclassified as "no Aqua session" and the test SKIPped.

**Fix** (commit `387d3a8`):
- Added a `label: String` field to `Paths` in `service.rs`, defaulting to
  `LABEL` ("dev.aiprovider.router"). Production callers are unaffected.
- `render_plist`, `install`, `uninstall`, and `status` now read `p.label`
  instead of the hardcoded constant.
- Test 1 uses `service::LABEL`; test 2 sets
  `paths.label = "dev.aiprovider.router-test"` so the two jobs coexist.
- `clean_stale` now takes the label explicitly.

**Gates**: 1230 lib tests pass, clippy clean, fmt clean, `aiproviderd`
binary builds.

## Final gate run + clippy 1.98 fix (12:56)

Stamped the v1.2.0 release. All four gates green:
- `key-leak-grep`: OK
- `check-doc-links`: 53 files, 126 links, all resolve
- `docs:book`: 12 chapters, book.html built
- `cargo clippy --all-targets -D warnings`: clean **after a fix**
- `cargo clippy --no-default-features --bin aiproviderd -D warnings`: clean
- `cargo test --lib`: 1298 passed

**The clippy fix (5 sites, clippy 1.98 / rustc floating):** clippy 0.1.98 (2026-09-01)
introduced `io_other_error` and `get_first`/`redundant_closure` firings on pre-existing code —
the "a -D warnings gate on floating stable goes red with no code change" case from the working
memory. Fixed rather than `#[allow]`'d:
- `core/vault.rs:124`: `std::io::Error::new(std::io::ErrorKind::Other, e)` → `std::io::Error::other(e)` (io_other_error)
- `bin/aiproviderd.rs` x3 (install/uninstall/status): `.map(|uid| service::domain(uid))` → `.map(service::domain)` (redundant_closure)
- `bin/aiproviderd.rs` main: `args.get(0).map(|s| s.as_str())` → `args.first().map(String::as_str)` (get_first)
No semantic change. fmt applied. The two aiproviderd lints only surfaced because `--all-targets`
compiles the `--no-default-features` binary target, which the earlier green default-features pass
hadn't touched.
