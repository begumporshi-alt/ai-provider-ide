### Two structural decisions, both forced by Rust rather than chosen

- **The context is a `trait PlanContext`, not a struct of `&'a dyn Fn` fields.** A struct holding
  `&'a dyn Fn(..)` forces every test to keep its closures alive longer than the context built from them;
  `&|pid| ...` is a borrow of a temporary and does not compile. A trait lets the fixture *be* the context,
  which is also what the TypeScript is (an object literal with methods).
- **`Candidate` moved out of `core::engine` into `core::planner`.** Its increment-7 doc-comment parked it in
  the engine only "because the planner itself is not ported yet"; the planner now owns its output type. The
  engine imports it, so no call site changed. `ProviderRow`/`ApiKeyRow`/`ModelRow` gained `Clone`, because the
  TypeScript's `Candidate` holds *references* and the port clones. **After removing the struct, `ModelRow`
  became unused in non-test engine code** — it is imported inside `mod tests` so a plain `cargo build` warns
  about nothing.

### Three provably-equivalent divergences (each pinned by a test)

1. **`rem_euclid` replaces JavaScript's `%` *plus* its negative `slice` indices.** `-1 % 3` is `-1`, and
   `slice(-1)`/`slice(0, -1)` count from the end — so `start = -1` on three keys means "begin at index 2",
   which is exactly `rem_euclid(3)`. Total and panic-free where a literal `%` would produce a `usize` panic.
2. **The TypeScript's `if (!ctx.pricingFor)` guard is unobservable** once an absent price is `None`: every
   rank is `None`, every comparison is `Equal`, and a stable sort is the identity. So `pricing_for` is a
   **required** trait method with no default body — this crate's rule — and "no pricing" is one of its
   answers rather than a missing one. (Note the tension with the crate's "no default body" rule and why the
   rule still wins: the optionality *is* the value.)
3. **Dedup key is a `(provider_id, native_id)` tuple**, not `` `${providerId} ${nativeId}` `` — the string
   collapses `("a b","c")` with `("a","b c")`.

### Two source behaviours kept, both now pinned

- **`orderCarriers` decides by `wanted.some(...)`, so ONE carrier asking for `cost_spread` reorders every
  other carrier on the list**, including providers whose own strategy is something else.
- **A *disabled* provider still claims its own qualifier.** `stripClientNamespace` and the qualified-id lookup
  read `ctx.providers` regardless of status, while `buildPlan` requires `enabled`. So `a/m1` resolves as
  qualified against a disabled `a`, `qualified` suppresses the bare-id fallback, and the plan comes back
  **empty** even though another enabled provider carries a model literally named `a/m1`. That is the source's
  "never silently reroute" rule reaching further than its comment describes.

### Environment / tooling notes that cost time

- `docs/dev-book/09-status.md` is a **markdown table**: a `|` inside a cell — e.g. the closure notation
  `&|pid|` — is read as a column separator and fails `build-dev-book` with "table row has 4 cells but the
  header has 2". Write around pipes in that file.
- An **orphaned doc comment** (a `///` block left where a struct used to be) attaches to the *next* item and
  trips clippy's `empty_line_after_doc_comments`. Use `//` for a comment that documents nothing.
